Weather App File Guide

A simple explanation of what each project file does

Project: Tropical Cyclone Information System

Prepared September 9, 2026

How the app works

The project has a public website, an admin portal, and a MySQL database. The public pages display information. Admin pages update information. PHP API files connect the browser to the database.

Admin edits storm data | v MySQL database: cyclone_db | v PHP API returns JSON | v JavaScript reads the JSON | v Public pages show the information
Filename note: There is no lunch.json. The file is .vscode/launch.json. It tells VS Code how to open the site in Chrome.

Root and VS Code files

index.html

The homepage. It contains the video hero, storm statistics, upcoming storm area, education links, and resource previews.

composer.json

Lists the PHP package required by the app. The project uses PHPMailer to send password-reset emails.

composer.lock

Records the exact versions of the installed PHP packages so the project uses predictable dependencies.

.gitignore

Tells Git which files should not be saved in the repository, such as temporary files or private configuration.

.vscode/launch.json

Defines a Chrome debugging setup for http://localhost:8080, using the project folder as the web root.

Admin folder

These PHP files are used by administrators to log in and manage cyclone records.

admin/auth.php

Checks whether an admin is logged in. If not, it redirects the visitor to login.php. This protects admin-only pages.

admin/login.php

Shows the login form and checks the username and password against the admins database table. A successful login creates a PHP session.

admin/logout.php

Clears the admin session, removes the session cookie, and sends the user back to the login page.

admin/forgot-password.php

Starts password recovery. It creates a six-digit code, saves it in the database, and emails it using PHPMailer.

admin/reset-password.php

Checks the six-digit code. If it is valid and not expired, it hashes and saves the new password.

admin/dashboard.php

Shows an admin overview: total cyclones, latest year, strongest storm, and recent records.

admin/cyclones.php

Shows historical cyclones in a searchable, filterable, paginated table.

admin/cyclone-form.php

Adds a new cyclone or edits an existing one. It validates names, dates, wind speeds, categories, and warning signals before saving.

admin/cyclone-delete.php

Deletes a historical cyclone. It only accepts a POST request, which helps prevent accidental deletion from a normal link.

admin/helpers.php

Contains shared admin functions for database connections, form values, error messages, CSS error classes, and dropdown options.

admin/nav.php

Displays the admin navigation bar and highlights the current admin section.

admin/partials/site-footer.php

Displays the footer used by admin pages.

Security reminder: The email account password is currently written directly in admin/forgot-password.php. It should be moved to a protected environment variable before deployment.

API folder

api/get_cyclones.php

Reads all historical cyclone rows from MySQL and returns them as JSON. Public JavaScript uses this for tables, statistics, charts, and comparisons.

api/get_upcoming_storm.php

Reads the active upcoming storm and returns it as JSON. If no storm is active, the public site displays an empty state.

Reusable partials

partials/header.html

A reusable public header containing the announcement bar, logo, navigation, Education menu, About and Contact links, and admin login link.

partials/footer.html

A reusable public footer containing site information and navigation links.

Several pages currently contain equivalent header and footer markup directly instead of loading these partial files dynamically.

JavaScript files

js/main.js

Shared browser behavior: mobile menu, Education dropdown, announcement dismissal, header effects, active links, and reveal animations.

js/home-overview.js

Loads cyclone data and calculates homepage totals, year range, average, strongest storm, busiest year, and newest cyclone.

js/storm-category.js

Converts sustained wind speed into a PAGASA-style category such as Tropical Depression, Typhoon, or Super Typhoon. Used by the admin cyclone form and the public comparison sandbox.

js/topic-models.js

Stores the education topics, titles, icons, summaries, and detailed text.

js/topic-detail-modal.js

Builds and controls the Education Hub popup. It supports closing, Escape, focus restoration, and keyboard navigation.

js/pages/analysis-comparison.js

Loads storms, finds similar storms, renders storm selectors, compares values, and displays winner or tie results.

js/pages/historical-data.js

Loads records, applies filters, creates the table and pagination, calculates statistics, and exports filtered CSV data.

js/pages/evacuation-guide.js

Creates the evacuation checklist, saves checked items in the browser, updates progress, and supports reset controls.

js/pages/preparedness-tips.js

Creates the preparedness checklist, saves its state in the browser, updates progress, and supports reset controls.

Vendor folder

vendor/autoload.php

Automatically loads installed PHP packages so the application can use PHPMailer.

vendor/phpmailer/

Third-party PHPMailer code used to send password-reset emails.

vendor/composer/

Composer-generated files that help PHP locate and load installed packages.

Vendor files normally should not be edited manually because they are generated or supplied by external packages.

Example: testing a storm on the Analysis Comparison page

When a visitor enters an upcoming storm, it is kept in this browser tab while navigating between pages.

  1. The Step 1 sandbox form validates the name, wind (30–500 km/h), and PAGASA category.
  2. Typing provides category guidance; pressing Apply Upcoming Storm fills the profile and saves the name, wind, and category in tab session storage.
  3. The Best Match panel ranks historical cyclones by wind closeness to the upcoming storm.
  4. The public homepage and admin dashboard show the same session value; refreshing the website or pressing Reset clears it.
